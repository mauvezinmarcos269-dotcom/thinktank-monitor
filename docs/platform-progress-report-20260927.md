# 智库报告实时监测平台当前进展汇报

更新时间：2026-09-27

本文面向“老师了解平台进展”和“后续开发排期”两个场景，概括当前平台已经具备的能力、近期代码整理情况、质量验证结果、仍需确认的问题和下一阶段开发路线。

## 一、建设目标

平台目标是长期追踪全球顶级智库、研究机构和重要期刊的重磅涉华研究成果，以美国顶级智库为主，英欧、国际组织和周边国家重要机构为辅。

平台重点处理的报告形态包括：

1. 篇幅一般不少于 20 页的 PDF 研究报告。
2. 无 PDF 但正文足够长、结构接近研究报告的网页长文。
3. 具备较强涉华相关性，或对中国、国际格局、中美竞争、产业链、安全、科技和全球治理有现实影响的研究成果。

平台最终需要为老师提供：

- 新报告发现与提醒。
- 原文正文保存和来源追踪。
- 全文中文翻译稿。
- 评论稿第一部分“主要观点”，约 1500-2000 字，通常包含 4 个及以上分论点。
- 评论稿第二部分“深层研判”，约 2000-2500 字，通常包含 4 个及以上分论点。
- 人工复核、重跑、复制、导出 Word / Markdown 和批量交付能力。

## 二、当前阶段结论

当前平台已经具备一条较完整的闭环：

1. 按来源发现候选报告。
2. 对候选进行去重、文档获取、页数或正文长度检查。
3. 判断是否涉华。
4. 将合格报告写入报告库。
5. 自动生成全文翻译、主要观点和深层研判。
6. 在前端进行人工复核。
7. 复核通过后导出 Word / Markdown，或复制评论稿给老师使用。

当前重点不是立即扩大到完全自动化，而是继续保持“小批量、可追踪、可复核”的运行方式。P0/P1 重点美国来源已形成较可靠的试运行基础；非美国来源仍建议按“只读审计 -> 小样本复核 -> 小批量试运行”逐步推进。

## 三、已具备的主要功能

### 1. 来源与机构治理

平台已支持按机构和来源管理监测入口，并记录来源类型、抓取频率、健康状态、最近抓取时间、报告数量、优先级和区域标签。

当前来源治理口径包括：

- P0：美国核心智库。
- P1：美国扩展重点来源。
- P2：英欧重点来源。
- P3：周边国家重点来源。
- P4：待校对或候选来源。

系统已区分“机构重要性”和“是否允许自动入库”。高优先级机构不等于可以直接自动抓取入库，仍需通过真实样本复核。

### 2. 抓取与候选报告

后端已具备 RSS 和 website 来源抓取能力，并支持：

- 候选发现。
- URL 规范化和去重。
- PDF 或网页长文正文获取。
- 20 页 PDF 门槛或网页长文长度门槛。
- 涉华相关性判断。
- 跳过原因记录。
- 抓取运行记录和候选明细查看。

设置页已支持查看每次抓取的候选报告、跳过原因、保存率和抓取错误，便于判断某个来源是否值得继续放行。

### 3. AI 翻译与评论稿

AI 流程已拆为多个阶段：

- 分块全文翻译。
- 分块分析笔记。
- 汇总生成主要观点。
- 汇总生成深层研判。
- 长度和结构校验。
- 失败后重试或人工触发重跑。

提示词已按老师需求约束字数、分论点数量和输出格式，避免只生成简短摘要。

### 4. 前端报告工作台

报告页当前已支持：

- 按关键词、复核状态、AI 状态、文档类型、成果完整度、智库和来源筛选。
- 快捷筛选“待老师复核”“可直接导出”“需重新处理”。
- 查看原文正文、全文翻译、主要观点和深层研判。
- 查看 AI 分块进度和复核历史。
- 复制评论稿、复制全文翻译、复制当前内容。
- 导出单篇 Word / Markdown。
- 批量复核和批量导出。

近期已将报告页重构为更清晰的“筛选 -> 阅读 -> 交付”工作流，老师打开页面后能更快定位待处理报告和可交付成果。

### 5. 设置与来源健康工作台

设置页当前已支持：

- 查看机构总数、重点机构、来源总数、启用来源和待配置来源机构。
- 查看来源健康概览。
- 查看候选验收重点。
- 添加新来源并立即试抓。
- 查看来源健康、准入策略、抓取历史和候选报告明细。
- 手动重试来源抓取。

近期已将设置页优化为“覆盖重点机构 -> 验收候选质量 -> 小批量试运行”的来源治理流程，更便于向非技术老师解释平台如何控制质量。

## 六、已确认或需持续注意的风险

### 1. 不能过早全量自动化

`pilot_crawl` 只表示来源通过小样本验证，可以小批量写入报告库。当前仍不建议直接扩大到全自动批量抓取，否则容易引入重复报告、短文档、导流页或通知噪声。

### 2. 网页长文需要人工把关

AEI 和 ECFR 等来源说明，网页长文有价值，但也可能出现转载页、导流页、短评论或非正式报告。网页长文应持续检查正文长度、原始出处和报告结构。

### 3. 阻塞来源不能因机构重要性硬推

CAP、Cato、Heritage 等来源重要性较高，但当前普通抓取入口存在阻塞或不稳定问题。建议先确认官方 feed、可访问入口、授权 API 或人工维护方式，再进入自动化。

### 4. 工作区历史改动较多

当前项目工作区存在大量未提交和未跟踪文件，其中许多是前期功能开发、文档、备份和测试文件。后续正式交付前建议整理一次提交或阶段性归档，形成可回退基线。

## 七、需要老师或你确认的问题

### 1. 来源范围确认

需要确认第一批稳定运行来源是否继续以以下机构为主：

- Brookings
- CFR
- CSIS
- PIIE
- AEI
- ECFR

同时确认 CAP、Cato、Heritage 是否暂缓自动化，只保留入口调研和人工维护。

### 2. 网页长文是否可作为正式报告

当前系统允许 AEI、ECFR 这类来源将足够长、结构接近报告的网页长文纳入候选。需要老师确认这种口径是否符合国发院交付要求。

### 3. 提醒频率

建议初期采用保守提醒：

- P0/P1 新报告入库：可即时提醒。
- AI 成果完成：可即时提醒。
- 普通来源、低优先级来源、抓取失败和候选跳过：进入每日摘要。

需要确认老师是否希望通过站内通知、邮件、企业微信或飞书接收提醒。

### 4. 导出格式

当前支持 Word 和 Markdown。需要确认最终交付标题采用：

- “智库报告编译成果”
- “全文翻译稿”
- “分析评论稿”
- 或国发院已有固定模板名称。

## 八、下一阶段开发路线

### 阶段 1：稳定小批量监测

目标：让已通过验证的美国重点来源持续稳定运行。

建议动作：

1. 每个 `pilot_crawl` 来源继续每次最多新增 1 篇。
2. 新增报告必须经过 AI 生成和前端复核。
3. 观察重复率、跳过原因、通知噪声和复核通过率。
4. 每周输出一次来源健康和报告成果摘要。

阶段确认点：

- 老师是否认可当前入库报告质量。
- 是否允许扩大单次新增数量。

### 阶段 2：扩展非美国重点来源

目标：在英欧、国际组织和周边国家中选择少量高价值来源试点。

建议动作：

1. 先做只读审计，不直接入库。
2. 对候选报告做人工抽查。
3. 为通过审计的来源补专用解析器。
4. 小样本入库并生成 AI 成果。

阶段确认点：

- 老师是否认可候选来源名单。
- 网页长文与 PDF 的准入口径是否一致。

### 阶段 3：提升 AI 成果质量

目标：让翻译稿和评论稿更接近老师可直接使用的决策咨询材料。

建议动作：

1. 抽样检查全文翻译是否漏译、压缩或误总结。
2. 检查主要观点是否达到 1500-2000 字、4 个以上分论点。
3. 检查深层研判是否达到 2000-2500 字、机制分析足够深入。
4. 沉淀常见复核意见，作为后续重跑提示词。

阶段确认点：

- 老师是否认可当前评论稿风格。
- 是否需要更偏政策建议、风险研判或学术综述。

### 阶段 4：完善提醒与交付

目标：减少老师主动检查平台的负担。

建议动作：

1. 配置每日摘要。
2. 配置重要报告即时提醒。
3. 明确提醒渠道。
4. 优化 Word 模板，方便老师审阅、批注和归档。

阶段确认点：

- 提醒频率是否合适。
- Word 模板是否符合国发院使用习惯。

### 阶段 5：部署与长期维护

目标：让平台稳定运行，而不是只在本地演示。

建议动作：

1. 整理 `.env` 和部署说明。
2. 固定数据库迁移流程。
3. 明确 Redis、Celery、MinIO、PostgreSQL 的部署方式。
4. 设置日志、备份和管理员账号。
5. 形成日常维护手册。

阶段确认点：

- 部署在本机、学院服务器还是云服务器。
- 是否需要多用户权限和外网访问。

## 九、建议的下一步

建议下一步不是继续盲目加功能，而是先和老师确认三件事：

1. 当前报告页和设置页的工作流是否清楚。
2. 第一批稳定运行来源名单是否合适。
3. AI 生成稿件的标题、字数和风格是否符合老师预期。

确认后，再进入“非美国重点来源扩展”和“提醒渠道配置”。
