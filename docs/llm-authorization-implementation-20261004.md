## 二、授权规则

1. `LLM_OUTBOUND_ENABLED` 默认 `false`。总开关关闭时，无论是否有授权都不能调用 LLM；设置为 `true` 也不会替代逐篇授权。
2. 两种用途分别记录：`relevance_sample` 为涉华抽样，`report_generation` 为全文翻译、分析分块及派生笔记的最终汇总、评论。两者不能互相替代。
3. 授权绑定标题和完整原文的 SHA-256、用途、策略版本、服务类型、完整端点和模型，并记录审批人/时间、撤销人/时间。生成阶段重新计算原文哈希，不信任可能陈旧的 `Report.content_hash`。
4. 抽样按单个来源、规范化 URL、文档版本绑定。后续批次同一文档且版本未变可使用该授权；不是整个来源的长期授权。候选只保存文档哈希和字符数，不新增一份正文副本。下一次采集会重新提取并核对文档版本，发生变化就重新待授权。
5. 抽样最多取正文开头、中部、结尾共 12000 字符，加标题和提示词；短于或等于 12000 字符的正文会全部发送。按全文计算版本，防止抽样外的原文变化被忽略。
6. 未授权的常规采集候选进入 `pending_relevance`，显示“待授权”，涉华结论仍为 `null`，不计入非涉华或模型失败，不创建正式报告和“新报告”通知。
7. 正式报告的 `pending`、成果“复核通过”以及管理员角色本身都不是外发授权。历史报告不自动补授权，聊天中对 `441`、`442` 的批准也不自动写入新表。
8. 授权人停用、降为非管理员或被删除后，其授权不可用于发送。撤销将停用该文档用途的所有仍有效记录，保留历史。

## 三、检查位置

- 自动调度在选择、加锁后均检查授权；先过滤已授权内容版本，再应用批次上限，避免历史未授权报告占满前几个名额。
- 手动 `retry-ai` 在重置任务/复核状态以及投递前检查，不满足时返回 403，不修改这些状态。
- 分块和 finalizer 在领取执行输入时检查；每次实际 HTTP POST 前再使用新数据库会话检查授权、当前文档版本及实际客户端目标。
- 老任务、过期恢复、旧整篇任务兼容入口及维护脚本不能绕过实际请求前的检查。分块后的 finalizer 投递也再次检查。
- 授权拒绝使用独立异常，不进入生成质量重试循环；执行器返回 `blocked`，不增加 AI 重试次数、不发模型失败通知。
- finalizer 拒绝将不同原文哈希的历史分析分块作为当前文档笔记外发。
- `check_siliconflow_models.py` 只使用固定无业务数据的探测提示词，但也遵守默认关闭的总开关。此脚本不具有报告外发授权功能。

授权检查不能撤回已经发出的内容。并行请求中已经通过检查并开始发送的请求可能仍然完成；撤销阻止其后的检查和请求。没有做跨数据库事务与远端 HTTP 的原子撤销，也不宣称能中断已经在运行的旧版 Worker。

## 四、后端接口

全部授权接口目前仅对管理员开放，教师权限未改动。`target_id` 在抽样用途下是候选 ID，在全文用途下是报告 ID。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/llm-authorizations/preview?scope=...&target_id=...` | 返回标题、字符数、文档哈希、数据用途、当前端点/模型、开关及匹配授权状态，不调用模型 |
| `GET /api/v1/llm-authorizations?scope=...&target_id=...` | 查看该用途、文档的授权历史，支持限制条数 |
| `POST /api/v1/llm-authorizations` | 显式批准预览的版本和目标；只写授权，不直接投递任务 |
| `POST /api/v1/llm-authorizations/revoke?scope=...&target_id=...` | 撤销该目标/用途的所有有效版本，重复撤销不产生额外变化 |

批准请求必须包含 `scope`、`target_id`、`document_hash`、`provider`、`endpoint`、`model`、`policy_version: 1` 和 `consent: "allow_external_processing"`。提交时重新读取文档和当前配置，预览过期返回 409，缺少明确同意或含额外字段返回 422。端点含用户凭据、查询参数或 fragment 时拒绝预览，避免回显配置密钥。

批准会替换同一目标、同一用途的旧有效授权，并保留旧记录和撤销信息；已有运行任务持有旧授权 ID 时会在下一次请求检查被阻止。撤销不改变另一种用途的授权。后续界面应禁用重复提交，并明确重新授权对进行中任务的影响。

**批准不直接排队，但不是任务暂停承诺。** 当总开关已开启，现有 `pending`/可重试任务可以在后续周期调度中使用新授权；候选也可以在下一次采集中使用已批准的抽样授权。未来审批界面必须清楚展示这一行为。
